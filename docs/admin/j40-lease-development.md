# J40 Lease 开发配置

启用 `m4_lease_api_enabled` 时，`memory_bytes` 必须覆盖每个表组常驻的恢复账户、同一次 Lease 请求的 gateway 和 owner 账户，以及每个表组的 Lease/到期工作保留容量。启动时根据表组数量、`max_etcd_request_bytes` 和内部 owner 传输预留校验该下限，配置不足会明确拒绝启动。

当前预留中每个恢复账户为 60,948,480 字节；owner 账户为 151,126,016 字节；gateway 账户按带 keys 的 TTL 请求计算，为 151,060,480 字节加上 `max(65,536, 3 × (max_etcd_request_bytes + 65,536) + 32,768)` 字节。以示例的 1,572,864 字节请求上限为例，Lease 和到期工作每表组另有 157,175,808 字节的保留容量，单表组最低为 525,258,752 字节；每增加一个表组还需增加一个恢复账户及一份该保留容量，共增加 218,124,288 字节。启用 owner forwarding 时，传输内存预留会从可用预算中先扣除。

示例配置为 owner forwarding 留有空间：在请求上限 1,572,864 字节、4 个并发内部请求时，owner transport 预留为 25,427,968 字节；示例 `memory_bytes` 为 671,088,640 字节。实际内存下限会按运行时的并发数和请求大小重新计算。

该下限只保证空闲账本有足够容量准入基本 Lease 请求、恢复账户和有界后台工作；其他并发请求与工作负载仍需额外预算。账本不是 JVM 或 HBase client 的完整内存上限，目标环境的容量和身份验收仍需单独完成。
